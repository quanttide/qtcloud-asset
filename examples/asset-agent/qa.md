# asset-agent 验证计划

## 概述

验证两个页面能否回答各自的设计问题。

## 验证项

**结构页（index.html）— 职责可见**

| 验证项 | 操作 | 通过标准 |
|:-------|:-----|:---------|
| 目录树 | 打开 index.html | 显示 `docs/drd/`、`src/frontend/`、`src/backend/` 三层目录结构 |
| 文件节点 | 检查子节点 | 每个目录下的文件（.md、.js、.go）正确显示 |
| 角色 badge | 检查目录右侧 | 有智能体挂载的目录显示「1 角色」标签 |
| 导航 | 点击顶部链接 | 跳转到 evolution.html |

**演化页（evolution.html）— 过程诊断**

| 验证项 | 操作 | 通过标准 |
|:-------|:-----|:---------|
| 版本网格 | 打开 evolution.html | 显示 3 列（DRD、前端、后端），每列从上到下排列 v1→v2→v3 |
| 触发边 | 检查蓝色箭头 | DRD → 前端/后端的箭头方向正确 |
| 反馈边 | 检查橙色虚线 | 前端/后端 → DRD 的箭头方向正确，线型为虚线 |
| 收敛标记 | 查看 v3 行 | v3 节点不再产生反馈边 |
| 图例 | 检查右下角 | 显示节点颜色、线型含义 |

**数据生成（app.py）**

| 验证项 | 操作 | 通过标准 |
|:-------|:-----|:---------|
| 目录扫描 | python app.py sample/ --output data.js | 正确扫描 sample/ 下的所有目录和文件 |
| 版本生成 | 加 --seed-traces | 生成 9 个版本节点和 10 条迭代边 |
| 无杂散边 | 检查 trigger/feedback | 只有预期路径（drd↔frontend、drd↔backend），无多余边 |
| 零外部依赖 | 检查 import | 无需 yaml、无 deprecation warning |

**业务假设验证**

| 验证项 | 操作 | 通过标准 |
|:-------|:-----|:---------|
| 独立迭代 | 修改 traces 使前端自增一版但不通知 DRD | 前端列版本 +1，无跨列新边 |
| 收敛 | 所有步骤不再产生 feedback | 演化图中所有边均为蓝色（无橙色），表示无活跃反馈 |
