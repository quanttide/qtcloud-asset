# 资产智能体协作壳 — 交互设计

文档状态：v2.0 已确认
角色：产品经理
日期：2026-05-16

---

1. 产品背景与目标

三位智能体（DRD、前端、后端）通过文件变化和事件驱动协作。当前缺乏工具让创始人直观理解两个问题：职责怎么划分的、协作效率怎么样。

目标：设计两个本地运行的页面，回答这两个问题。

用户：创始人本人，零配置启动，开箱即用。

2. 设计原则

职责可见：打开就知道谁管什么、谁依赖谁。

过程可诊：版本迭代图暴露瓶颈、反馈闭环、迭代收敛。

不做瀑布：不假设版本号同步推进，每个角色独立迭代。

减法优先：能用一个视图解决的问题不用两个，能去掉的面板就去掉。

3. 双页设计

3.1 资产结构页（index.html）

用途：回答「这事谁负责、上下游是谁」。

布局：整屏目录树。

树中显示：
- 目录节点（📁），按实际资产目录结构展开
- 文件节点（📄），资产文件
- 角色 badge（🤖），标注在每个目录右侧，表示该目录挂载的智能体

交互：
- 展开/折叠目录
- 顶部导航链接跳到演化页

不包含：
- 协作关系图（角色拓扑由树中的 badge 表达）
- 事件时间线
- 详情面板

3.2 资产演化页（evolution.html）

用途：回答「这个功能迭代了多少轮、卡在哪、怎么收敛的」。

布局：全屏版本网格图，vis-network 渲染。

网格结构：
- 三列：DRD、前端、后端
- 每列从上到下排列版本（v1、v2、v3...）
- 版本节点为圆角矩形，蓝色边框，白色文字

边的样式：
- 蓝色实线箭头：设计驱动（DRD → 前端/后端）
- 橙色虚线箭头：反馈迭代（前端/后端 → DRD）

图例显示在右下角，标注收敛状态。

交互：
- 拖拽节点调整位置
- 滚轮缩放
- 顶部导航链接跳到结构页

不包含：
- 点击联动（版本节点不需要与树联动）
- 事件报文展开（事件信息编码在边的样式中）
- 手动触发模拟

4. 数据流

```
agent_rules.yaml    sample/目录        traces（app.py内嵌）
       │                │                  │
       └────────────────┼──────────────────┘
                        ▼
                   app.py
                        │
                        ▼
                    data.js
                   ┌───┴───┐
                   ▼       ▼
            index.html  evolution.html
```

两个页面共享同一份 `data.js`，各自过滤需要的节点类型。结构页只读 Dir + File + Agent，演化页只读 Version。

5. 技术实现

- 前端：vanilla HTML + vis-network（演化页）
- 数据：data.js（静态 JSON，全局变量 `window.graphData`）
- 生成：app.py + agent_rules.yaml，可从真实目录产出 data.js
- 启动：双击 index.html 或 evolution.html，零配置

6. 使用场景

场景 1：新功能接手
打开结构页，看目录树和角色 badge，知道谁管哪块。

场景 2：排查协作瓶颈
打开演化页。如果某一列反复出现"问题→反馈→改版"的循环，说明这个角色一直在返工。如果橙色虚线集中在某条路径上，说明上下游协作有问题。

场景 3：验收迭代收敛
演化页中，所有版本节点不再产生新的反馈边，说明功能收敛了。
