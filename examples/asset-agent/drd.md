# 图数据模型 — 业务假设

文档状态：v2.0 已确认
领域：数字资产管理 × 智能体协作
日期：2026-05-16

---

1. 概述

图数据模型由 `graphNodes` 和 `graphEdges` 构成。三个智能体协作完成一个功能从设计到交付的全过程，各自独立迭代，通过事件驱动交叉。

2. 目录结构即组织分工

```
仓库/
├── docs/drd/       ← drd-agent 管辖（设计）
├── src/frontend/   ← code-frontend 管辖
└── src/backend/    ← code-backend 管辖
```

谁挂载在哪个目录，谁对该目录的资产负责。业务假设是智能体的职责边界由目录路径定义，不靠命名约定。

3. 智能体即业务角色

| 智能体 | 角色 | 职责 |
|:-------|:-----|:-----|
| drd-agent | 需求分析师 | 产出领域需求文档 |
| code-frontend-agent | 前端开发者 | 实现前端页面 |
| code-backend-agent | 后端开发者 | 实现后端接口 |

4. 三种边即三种协作方式

| 边类型 | 业务含义 | 线型 |
|:-------|:---------|:-----|
| write | 生产者产出文件 | 灰色虚线 |
| trigger | 设计驱动开发 | 蓝色实线 |
| feedback | 实现发现问题反馈设计 | 橙色虚线 |

5. 独立版本线

每个智能体有自己的版本计数器，不受其他人影响。

- DRD v1 发布 → 触发前端 v1 和后端 v1
- 前端发现缺退款入口 → 反馈 DRD → DRD 改到 v2
- 后端修响应格式（自迭代 v1→v1.1）→ 不需要通知 DRD
- 什么时候该自己改、什么时候该触发别人，决策权在智能体手里

6. 迭代收敛

收敛不是「所有人都做到 v3」。收敛是「没有再提反馈了」。

- 前端迭代到满意为止，做出 v3 时不再提反馈 → 前端收敛
- 后端在 v2 就满意了 → 后端收敛
- DRD 改到前后端没有新反馈 → DRD 收敛
- 每方各自收敛时，迭代结束

7. 关键业务约定

| 编号 | 假设 |
|:-----|:-----|
| A01 | 组织分工映射为目录树 |
| A02 | 角色职责边界清晰 |
| A03 | 每个角色独立迭代，不要求版本号同步 |
| A04 | 触发和反馈是唯一的跨线连接点，没有事件就没有关系 |
| A05 | 自迭代（内部改版）不产生触发，不通知他人 |
| A06 | 收敛标准是隐式的（无更多反馈），每方自行判断 |
